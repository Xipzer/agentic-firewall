# What if the model itself turns against us?

afw will consult a language model (the "adviser", v0.3). That model is a dependency someone else controls. This document assumes it can go bad and shows why that cannot hurt the network.

## Ways it can go bad

All of these look identical from our side: the answers can no longer be trusted.

| How | Example |
|---|---|
| The provider is compromised, or acts maliciously | An insider or intruder at the company changes what the model returns |
| The request is redirected | DNS tampering, a proxy setting, a changed base URL in a config file, a stolen or fake certificate |
| A middleman sits in the path | A reseller or routing service between us and the real provider |
| The model is swapped or tampered with | A poisoned local model download; a quietly changed remote model version |
| The model is honest but steered | Attacker-written text in what it reads tells it what to say (prompt injection) |
| The answers stop | Outage, rate limit, expired key, deliberate silence |

[judgement] A full takeover of a major provider is the least likely of these. Redirection, a middleman, a tampered local model and steering by attacker text are the realistic ones, and the last is close to certain to be attempted. The design does not depend on which one happens.

## The principle

**Do not try to detect a bad model first. Bound what any answer can do.** The adviser is treated exactly like a stranger on the internet who happens to send advice.

## What a fully hostile adviser can and cannot do (built and tested)

| It tries to... | Result | Why |
|---|---|---|
| Block something we need (router, resolver, a bank, your phone) | Refused | Protected subjects are untouchable; it may only speak about sources the firewall's **own** evidence already flagged; trusted users are judged on proven evidence only |
| Block anything at all | Cannot | Its answer is never executed. It becomes weighted, **unproven** evidence, and unproven evidence can slow a source but never block one |
| Unblock the attacker | Refused | Only a person can lift an action. The guard refuses `allow` from every non-human tier |
| Reach the firewall, the off switch, mode changes or keys | No path | It has one door: a socket offering redacted briefings and a proposal form. Admin commands are on a different socket it cannot open |
| Learn the layout of the network | Mostly not | Briefings replace every internal, local and protected address with a stable pseudonym and drop machine names |
| Plant instructions for the next model (memory poisoning) | No effect | Its words are stored clipped and escaped in a record that briefings never include. Verdicts and explanations use afw's own wording |
| Spread through crosstalk to other nodes | Cannot | Decisions that exist only because of adviser evidence are never published to peers |
| Flood us with proposals or run up cost | Capped | Hourly proposal limit; incidents queued for the model are rationed per hour and day |
| Go silent | Nothing happens | The fast tier and every rail work with no adviser at all (the lab tests run that way) |

**Worst case, measured in the test `TestCompromisedAdviserIsBounded`:** a source the firewall was already watching gets its new inbound connections rate-limited. By repeating itself the adviser can keep that up only while the firewall's own flag is fresh, so it lapses within about an hour and a half of the source last doing something suspicious. Replies to our own traffic are never affected.

## Catching it anyway

Some answers no honest adviser would give: asking to lift a block, naming a protected or internal address it was never shown, naming a source the firewall has seen nothing from, or returning something that is not one well-formed proposal. Each is a **strike**. Three strikes in 24 hours and afw:

1. suspends the adviser,
2. undoes everything it influenced,
3. sends a critical alert to a person, who runs `afw analyst resume` after checking.

## What is left

- **It sees what we send.** That is attacker addresses, timings and afw's own wording. Not your devices, not traffic content.
- **It can mislead you.** A compromised model can write a persuasive summary recommending a bad decision. Model-written text is always labelled as such and is never the only account: the fast tier's explanations are generated by code.
- **It can waste the budget it is given**, up to the caps.

## Binding rules for the v0.3 client (not built yet)

- The model runs in a **separate, unprivileged process** whose only access to afw is the adviser socket. It holds the API key; afw never does.
- **HTTPS only, no redirects followed, no proxy settings honoured, base URL fixed in a root-owned file**, with optional certificate pinning.
- The model gets **no tools**: it cannot run commands, fetch URLs or read files. It answers one form.
- **Known-answer checks**: now and then it is asked about a made-up incident with an obvious right answer. A wrong answer is a strike. The checks are generated fresh on the machine and never stored in this public repository, so the answers cannot be looked up or learned in advance ([testing-rules.md](testing-rules.md)). This detects a swapped or weakened model, not a careful adversary; the bounds above do not depend on it.
- **Who answered is recorded**: the model and version behind every answer are logged, and a change raises an alert.
- **Internet research, if ever added, is a bonus**: whatever it finds is unproven evidence, exactly like the adviser's own advice, and it is switched off for every benchmark.
- Optional **second opinion**: two independent providers must agree before advice counts at all.
- A **local model** gets exactly the same treatment. Running it yourself removes the network path, not the need for the bounds.

## Turning the door on

```yaml
analyst:
  socket: /run/afw/adviser.sock   # empty (the default) means no adviser
  provider: local-llm             # a label for logs and alerts
  trust: 0.6                      # scales its confidence; it can never block whatever this is
  proposals_per_hour: 30
```
